# 🌱 Sprout — คู่มือสั่งงาน AI สำหรับผู้บริหาร (Prompt Playbook)

เอกสารนี้ช่วยให้ผู้บริหาร/เจ้าของผลิตภัณฑ์ "สั่งงาน" ทีม AI ให้สร้างและปรับแอป **Sprout**
(แพลตฟอร์มปล่อยสินเชื่อดิจิทัล) ได้ด้วยภาษาธรรมดา ไม่ต้องเขียนโค้ด

> วิธีใช้: เลือกหัวข้อที่ต้องการ → ก็อปปี้ "คำสั่งตัวอย่าง" ไปพิมพ์ → ดูช่อง "ผลลัพธ์ที่จะได้"
> ว่าตรงกับที่ต้องการไหม แล้วปรับถ้อยคำได้ตามใจ

---

## 📌 Sprout คืออะไร (บริบทสั้น ๆ)

Sprout มี 3 หน้าจอหลักทำงานร่วมกัน + ฐานข้อมูลกลาง:

| ส่วน | ใครใช้ | ทำอะไร |
|---|---|---|
| **App ลูกค้า** (`/app`) | ผู้ขอสินเชื่อ | สมัคร, ยืนยันตัวตน (e-KYC + selfie), อัปโหลดเอกสาร, ดูสถานะ |
| **Officer Console** (`/staff`) | เจ้าหน้าที่สินเชื่อ | รีวิว, ให้คะแนน, อนุมัติ/ปฏิเสธ, ส่งต่อผู้จัดการ (maker–checker) |
| **Back Office** (`/admin`) | ทีมตั้งค่า | ตั้งกฎ prescreen, ผลิตภัณฑ์, เอกสาร, เครดิตบูโร, บัญชีพนักงาน |
| **ฐานข้อมูล** (Supabase) | ระบบ | เก็บเคส, ลูกค้า, กฎ, สิทธิ์ผู้ใช้ (ปลอดภัยด้วย RLS) |

---

## 🎯 หลักการสั่งงานให้ได้ผลดี

1. **บอกว่า "ใคร" เห็นและ "ทำไม"** — เช่น *"ให้เจ้าหน้าที่เห็นเหตุผลตอน decline"* ดีกว่าแค่ *"เพิ่มช่องเหตุผล"*
2. **สั่งเป็นผลลัพธ์ ไม่ต้องสั่งเป็นเทคนิค** — พูดถึงสิ่งที่ผู้ใช้ควรได้ ไม่ต้องระบุชื่อไฟล์/ตาราง
3. **อ้างของจริง** — เลขเคส (เช่น `SV671962`), เมนู, หรือแนบภาพหน้าจอ ช่วยให้ตรงจุด
4. **ขอให้ทดสอบด้วย** — เติม *"ทดสอบให้ด้วยว่าใช้งานได้จริง"* จะได้ผลตรวจสอบกลับมา
5. **สั่งทีละก้าว** — งานใหญ่แตกเป็นคำสั่งย่อย ตรวจทีละอันแล้วค่อยไปต่อ

## 🧩 คลังคำสั่งตามหมวด (คำสั่ง → ผลลัพธ์ที่จะได้)

### A. ฟีเจอร์ฝั่งลูกค้า (App)

| คำสั่งตัวอย่าง | ผลลัพธ์ที่จะได้ |
|---|---|
| *"หน้า Home ให้แสดงชื่อลูกค้าและวงเงินเครดิต ถ้าเพิ่งสมัครให้เป็น 0"* | ทักทายด้วยชื่อจริงจากโปรไฟล์; ลูกค้าใหม่เห็นเครดิต 0 ไม่ใช่ค่าหลอก |
| *"เพิ่มขั้นตอน selfie หลังถ่ายบัตรประชาชน ให้กระพริบตา หันซ้าย-ขวา แล้ว capture อัตโนมัติ และให้ preview ก่อนยืนยัน"* | ระบบตรวจใบหน้าแบบ guided liveness + ให้ดูรูปก่อนส่ง |
| *"ตอนเลือกธนาคาร ให้เสิร์ชชื่อธนาคารได้"* | ช่องเลือกธนาคารแบบพิมพ์ค้นหา |
| *"เอาหนี้ที่ disburse แล้วยังไม่จ่ายคืนมาแสดงเป็นภาระหนี้ ถ้าไม่มีให้เป็น 0"* | ดึงหนี้คงค้างอัตโนมัติจากสินเชื่อที่เคยอนุมัติ (ผูกด้วยเลขบัตรประชาชน) |
| *"ให้กดปุ่ม Back แล้วกลับหน้าก่อนหน้าเสมอ แก้ทั้งแอป"* | ปุ่มย้อนกลับทำงานถูกต้องทุกหน้า |
| *"ให้แสดงว่าลูกค้าค้างอยู่ step ไหน และกดทำต่อ (resume) ได้"* | หน้า Home บอกความคืบหน้า + ปุ่มทำต่อจากจุดเดิม |

### B. Officer Console (เจ้าหน้าที่สินเชื่อ)

| คำสั่งตัวอย่าง | ผลลัพธ์ที่จะได้ |
|---|---|
| *"แม้จะ Decline ต้องมีเหตุผลแสดงด้วย และต้องมี approver คนละคนตัดสิน และ approver ส่งเรื่องให้ manager ได้"* | บังคับใส่เหตุผลตอนปฏิเสธ; แยกคนรีวิว/คนอนุมัติ (maker–checker); มีปุ่มส่งต่อผู้จัดการพร้อมโน้ต |
| *"แสดงวันเวลาที่ยื่นคำขอ เรียงจากเก่าไปใหม่ และเคสค้างเกิน 1 วันให้เป็นสีต่าง"* | คิวงานโชว์เวลายื่น + ไฮไลต์สีแดงเคสที่ค้างนาน |
| *"ให้เจ้าหน้าที่เห็นรูปบัตรและ selfie ตอน underwrite ในส่วนข้อมูลลูกค้า"* | การ์ด Identity แสดงรูปบัตรหน้า-หลัง + selfie |
| *"อธิบายว่าคะแนนแต่ละตัวคิดจากสูตรอะไร"* | หน้า Score แสดง 5 องค์ประกอบ พร้อมสูตรคำนวณโปร่งใส |
| *"บอกเจ้าหน้าที่ว่าทำไมเคสนี้ไม่ผ่าน auto pre-screen ทุกข้อ"* | แถบสรุปเหตุผลที่ตกทุกกฎที่ไม่ผ่าน |
| *"เอกสารที่ลูกค้าอัปโหลด เจ้าหน้าที่ยังไม่เห็น ให้แก้"* | เอกสารแสดงในคอนโซล + ตั้งสถานะ Verified/Review/Re-request ได้ |

### C. Back Office (การตั้งค่า)

| คำสั่งตัวอย่าง | ผลลัพธ์ที่จะได้ |
|---|---|
| *"กฎ prescreening ให้เลือกผลิตภัณฑ์ก่อน แล้วตั้งกฎเป็นของผลิตภัณฑ์นั้นโดยเฉพาะ"* | ตั้งกฎแยกรายผลิตภัณฑ์ + ปุ่ม Save/Reset |
| *"สร้างฐานข้อมูลเครดิตบูโรที่มีเลขบัตรและคะแนน เช่น Somchai 650 คะแนน"* | ตาราง credit_bureau + แท็บจัดการใน Back Office |
| *"ทำ Back Office ให้ดูทันสมัย สีเข้ากับแอป และเหมาะกับจอ desktop"* | คอนโซลแบบ sidebar สีกรมท่า จัดวางเต็มจอ |
| *"บนมือถือแถบเมนูหาย ดูรก ปรับให้ใช้ง่าย"* | แถบบนสลิม + แถวแท็บเลื่อนได้ + ปุ่มลัดเปิดแอป |
| *"ทดสอบว่ากฎ prescreening ของแต่ละผลิตภัณฑ์ตรวจจริง และระบุทุกกฎที่ไม่ผ่าน"* | ผลทดสอบยืนยันว่ากฎถูกบังคับใช้จริง ครบทุกข้อ |

### D. ฐานข้อมูล & ความปลอดภัย

| คำสั่งตัวอย่าง | ผลลัพธ์ที่จะได้ |
|---|---|
| *"ควรมีฐานข้อมูลเก็บข้อมูลลูกค้า"* | ตาราง customers + บันทึกชื่อ/มือถือ/รายได้ตอนสมัคร |
| *"เอา mock/hardcode data ออกให้หมด ใช้ค่าที่รับจากผู้ใช้จริงทั้งหมด"* | ทุกหน้าจอแสดงข้อมูลจริงจากผู้ใช้ ไม่มีค่าปลอม |
| *"ลืม username/password เจ้าหน้าที่"* | รีเซ็ตรหัส + แจ้งบัญชีที่ถูกต้อง |
| *"เพิ่มบัญชีผู้จัดการไว้รับเคสที่ส่งต่อ"* | บัญชี role `manager` สำหรับตัดสินเคสที่ escalate |

## 🔁 ตัวอย่างการสั่งงานแบบครบวงจร (End-to-End)

**เป้าหมาย:** ทำ workflow อนุมัติสินเชื่อให้รัดกุมแบบธนาคารจริง

1. *"ให้คนรีวิวกับคนอนุมัติเป็นคนละคน ห้ามคนเดียวทำทั้งสองบทบาท"*
   → ระบบ maker–checker + ล็อกไม่ให้คนรีวิวตัดสินเคสตัวเอง
2. *"ตอนปฏิเสธต้องระบุเหตุผล และเหตุผลต้องแสดงให้ลูกค้าและใน audit log"*
   → บังคับเหตุผล + บันทึกครบ
3. *"ให้ผู้อนุมัติส่งเคสยาก ๆ ต่อให้ผู้จัดการตัดสิน พร้อมโน้ต"*
   → ปุ่มส่งต่อผู้จัดการ + สถานะ "รอผู้จัดการ"
4. *"ทดสอบทั้ง flow ให้ดูว่าใช้ได้จริง แล้วสรุปผล"*
   → ได้ผลทดสอบ + ลิงก์ให้ลองใช้

**สิ่งที่ได้กลับมาทุกครั้ง:** สรุปสิ่งที่แก้, จุดที่ต้องสังเกต, ลิงก์ทดสอบ,
และคำถามกลับถ้ามีทางเลือกที่ต้องตัดสินใจ

## ✅ รูปแบบ "คำตอบ" ที่ผู้บริหารจะได้รับ

หลังสั่งงานแต่ละครั้ง ระบบจะตอบกลับเป็นแพตเทิร์นเดิมเสมอ:

- **สรุปสิ่งที่ทำ** — เป็นข้อ ๆ ว่าปรับอะไรบ้าง (ภาษาธุรกิจ ไม่ใช่ศัพท์เทคนิค)
- **ผลกระทบ/จุดสังเกต** — ถ้ามีข้อมูลเก่า หรือข้อจำกัดที่ควรรู้ จะแจ้งตรง ๆ
- **วิธีลองใช้** — บัญชีทดสอบ, ลิงก์, ขั้นตอนกดดู
- **คำถามกลับ (ถ้ามี)** — เมื่อมีทางเลือกที่ต้องให้ผู้บริหารตัดสินใจ ไม่เดาเอง
- **ปล่อยขึ้นระบบแล้ว** — โค้ดถูก commit/push ให้อัตโนมัติ

## 💡 เคล็ดลับปิดท้าย

- อยากได้ไอเดียก่อนลงมือ: *"เสนอ 3 แนวทางพร้อมข้อดีข้อเสีย แล้วแนะนำอันที่ดีที่สุด"*
- อยากตรวจคุณภาพ: *"รีวิวโค้ดที่เพิ่งแก้ หาบั๊กและจุดที่ปรับให้ดีขึ้นได้"*
- อยากได้รายงาน: *"สรุปสถานะฟีเจอร์ทั้งหมดที่ทำมาเป็นตาราง"*
- ไม่แน่ใจว่าสั่งได้ไหม: ถามตรง ๆ ได้เลย เช่น *"ทำ X ได้ไหม ถ้าได้ต้องเตรียมอะไร"*
